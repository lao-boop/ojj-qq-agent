# Mac 微信双联系人汇报试运行

角色：员工“一鸣”提交汇报，老板“老”接收定时汇总并查询详情。程序在两个指定的置顶私聊之间切换，沿用已经验证的单次发送核验。当前不接管其他联系人或群聊。

这是一版前台桌面试运行：收信来自窗口文字识别，保存的是识别到的完整汇报正文及局部截图证据，未人工核对，不能等同于微信服务端原始消息。默认用本地检索和文字摘录，不需要模型密钥。配置外部模型后，现有模型功能也仅用于挑选可核对的原文片段，不是能自由操作电脑的 AI。

## 先核对联系人，再运行

沿用现有 `~/wechat-assistant/pilot-app` 和 `.venv`，无需重装依赖。这个入口与单联系人入口分别保存数据，旧的单联系人记录不会自动发给老板。

1. 在原运行终端按 Ctrl+C 停止单联系人程序。支持的两个入口共用桌面锁，不能同时操作微信。
2. 在小号微信里，人工确认“一鸣”和“老”都是唯一备注的**私聊联系人**，分别置顶，使两人的完整备注同时显示在左侧列表。不要用同名群聊。
3. 手动打开其中一个私聊，两个聊天的输入框都留空。浅色界面，关闭弹窗、设置及独立聊天窗口，保持主窗口可见、位置尺寸不变、Mac 唤醒。
4. 程序会反复切换前台微信并使用剪贴板。运行期间让出微信的点击、滚动、输入和复制操作；需要操作时先 Ctrl+C 停止。

先检查本地服务，此命令不操作微信、不调用模型：

```bash
cd "$HOME/wechat-assistant/pilot-app"
bash scripts/run-mac-routing.command "一鸣" "老" --check-service
```

再检查侧栏切换。该检查会激活微信、点击两个私聊并核对空白输入框，但不发消息、不保存聊天截图：

```bash
bash scripts/run-mac-routing.command "一鸣" "老" --check-contacts
```

出现 `CONTACTS_OK` 后，用一分钟汇总周期试运行：

```bash
bash scripts/run-mac-routing.command "一鸣" "老" --interval 60
```

启动会分别向员工和老板发送一条校准通知，确认两个聊天的输入区和绿色发送气泡，再显示 `READY`。第一次启动会跳过启动时可见的旧测试指令；**等 READY 后使用新的请求编号提交**。此后重启保留已处理编号及未处理的已存汇报。

## 完整流程验收

请用“一鸣”账号向小号发：

```text
汇报 A101 合同已确认，预计周五回款，目前尚未到账 #END
```

员工应看到 `已记录汇报 [R000001]，将按汇总周期提交老板。`（编号以实际回复为准）。一分钟周期到期后，程序会切换到“老”，发送工作汇报。GUI 操作耗时可能让发送略晚于周期；不要提前手动发“汇总”替代这次定时验证。

让“老”向小号发以下指令，可逐条验证查询；每次使用新请求编号：

```text
汇总 Q101 #END
详情 Q102 R000001 #END
查询 Q103 一鸣回款的细节 #END
```

`详情` 返回该编号的完整识别正文、员工、收到时间及来源；`查询` 用姓名、关键词、日期或上次查询上下文检索，再给出原文摘录。普通自由聊天不会触发回复。当前没有启用大模型时，这种查询是本地规则检索，并非模型理解。

需要更正时，由“一鸣”发送新编号，例如：

```text
汇报 A102 更正：回款推迟至下周一，目前尚未到账 #END
```

更正作为新记录保存，旧文保留；老板按关键词查询可以同时看到两条记录。相同编号不重复处理，编号相同但内容不同会跳过并提示，不覆盖旧记录。员工不能通过查询指令读取老板端汇总；老板发送“汇报”也不会被当成员工数据入库。

只有“一鸣”账号可供测试时，仍可验证员工提交及老板聊天中的发出气泡；老板发起追问这一段须等有人能从“老”的账号发来指令后再实测。不要从小号自己发查询冒充老板来信。

完成试运行后，Ctrl+C 停止，用默认五分钟周期重新启动：

```bash
bash scripts/run-mac-routing.command "一鸣" "老"
```

## 数据和停止条件

- 数据位于 `~/wechat-assistant/routing-data/<角色组合散列>/`：`scope.json` 保存角色，`reports.json` 保存正文及通知状态，`pilot.sqlite` 保存请求去重和操作状态，`evidence/` 保存已处理指令的局部截图。目录仅当前用户可读写。不要删除数据来强行重发。
- 单联系人旧记录仍在 `~/wechat-assistant/pilot-data/`。本入口不会导入它们；新目录的记录编号独立。
- 切换前核对空白输入框，仅点击侧栏中唯一匹配的配置联系人；点击后再次精确核对聊天标题。未找到、重复、意外切换聊天或移动窗口时停止，避免在错误聊天读取或发送。
- `SEND_VISIBLE` 是本机画面核验，不是对方送达或已读回执。`SEND_UNKNOWN` 时停止并保存状态，不自动重发。已经保存的原文仍可用新查询编号查看；未确认的汇总批次不会自动再次推送。
- 首次启动只接收 READY 后的新请求；正常重启可处理当前画面上仍完整可见、尚未处理的指令。屏幕外消息、锁屏、休眠、图片、语音和附件都不属于此版的完整收集能力；程序不向上翻聊天记录。试点请逐条提交，避免消息突发滚出窗口。

## 验证范围

截至 2026-11-02，用户在 Mac 上已验证单联系人汇报、汇总查询、完整详情，以及单条自定义汇报发送到“老”的聊天。双联系人自动侧栏切换及连续定时转报尚需在该 Mac 上验证。

云端测试使用模拟桌面和真实本地 Node 汇报服务，覆盖两次一致识别、角色校验、员工回执、周期汇总给老板、详情、关键词追问、更正保留、重启去重、未确认不重发、错误点击和草稿阻止切换。测试不操作真实微信：

```bash
python3 -W error::ResourceWarning -m unittest discover -s test -p 'mac_*_test.py' -v
```
