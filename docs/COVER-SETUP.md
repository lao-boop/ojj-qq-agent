# 翻唱配置与测试

当前翻唱是 RVC 声线转换：输入一段语音、清唱或歌曲，保留原音频的内容与旋律，转换为所选声线。朗读、原创音乐、语音识别是另外的服务；MiniMax TTS token 不能当作 Replicate token。普通说话不会仅靠变声变成带旋律的歌。

## 第一次开通

1. 在 https://replicate.com 注册/登录自己的账号。
2. 打开 https://replicate.com/zsxkib/realistic-voice-cloning ，确认模型对你的账号可用。先查看页面提供的音色及价格，不假设免费。
3. 在 https://replicate.com/account/api-tokens 创建 token，只在自己电脑输入。实际生成需要按平台提示开通计费或有可用额度。配置向导只读取模型信息，不发起收费的翻唱任务。
4. Mac 停止机器人后，更新代码并运行：

```bash
cd ~/qq-agent-dev/ojj-qq-agent
git pull --ff-only origin main
~/qq-agent-dev/python-env/bin/python scripts/configure_cover.py
npm start
```

向导保留原有 QQ、DeepSeek、MiniMax、语音识别配置，在本地隐藏输入 token；核验实际模型接口，列出服务返回的现成音色，并固定该模型版本。没有自己的 RVC 模型时选择现成音色，不选 CUSTOM。CUSTOM 需要服务可访问的 RVC 模型 HTTPS 下载地址。原配置以私有权限备份在 `~/.qq-agent-backups/`。

如果 token、模型权限、模型接口或音色核验失败，向导不修改配置；先修正对应问题。仅配置成功不保证余额充足或每次任务成功。

## 测试

- 先发一段 5–10 秒清唱，随后说“翻唱我刚才那段音频”。
- 或先说“翻唱我下一条语音”，等机器人确认等待，再发要处理的音频。准备指令本身不作为素材。等待任务存在当前聊天的进程内状态中，10 分钟后过期，重启后需重新下达指令，可说“取消翻唱”。群聊待处理任务不能由另一位用户接管。
- 使用已配置的目标声线。没有目标模型时不能保证与 MiniMax 朗读音色相同。
- 用户点具体歌名时仍需本地曲库中有精确匹配的音频；该模块不自动提供全网歌曲搜索或下载。
- 上传到云端的是目标音频本身，处理与计费以 Replicate 平台为准。

## 执行状态

服务开关、token 和音色不足会明确反馈，不把“会聊天”当作“会翻唱”。音频解码、转码成功后才上传；服务没有输出音频或返回失败不记录为交付成功。一次请求不自动重提 prediction；超时或结果未知时查看平台任务 ID，避免重复消费。QQ 语音发送允许更长的转码等待，仍以回执为准。

自动测试使用模拟 Replicate/QQ 服务校验参数和执行流程，并非真实收费模型的听感验收。账号开通后仍需用短音频在本机测试。
