# 分阶段意图理解

启用条件为 `chat.agents.enabled: true`；默认关闭，方便渐进接入和回退。

## 流程

1. 现有适配器提供原始指令、文件文本、图片描述、语音转写和读取失败信息。
2. IntentRecognizer 输出严格结构：act、targetId、kind、goal、agents、slots、exclude、missing、clarification。
3. UnderstandingPipeline 根据当前会话的任务更新参数；已确认但本轮未提及的字段保留。
4. 通用校验检查目标存在、指代歧义、任务状态、缺失参数及格式；领域校验器只读查询实际资源。
5. 明确后才交给 Manager，不能凭意图识别模型自己声称“曲库里有”直接执行。

意图请求使用 OpenAI 兼容的 `response_format: {"type":"json_object"}`。不支持该参数的模型服务可在 `llm.jsonMode` 设置 `false`，仍保留本地严格校验。JSON 格式、必需字段、枚举不合规或输出截断时，最多重新解析一次；保留原始指令及排除条件，不为了通过校验忽略用户要求。两次都失败则不建立任务、不执行工具。

网络/认证/额度/限流/模型名称/请求参数/超时错误与结构错误分别反馈；不将服务故障当作格式问题重新提交。原 HTTP 客户端的临时故障重试仍然适用。日志中的 `意图输出校验未通过` 和 `意图理解失败` 记录错误类别，不输出原始模型内容或密钥。模型认证成功和 JSON 合法都不代表语义一定正确，仍需要后续业务核验。

act 区分新建 create、修改 update、否定 reject、取消 cancel、进度 status 和普通对话 chat。
遇到“不要做/没让你唱”等否定语句却被判为新建，会额外复核一次；仍有矛盾则追问，不执行。
不是每条消息都增加复核请求；复杂歧义也可直接追问。模型结果不符合结构约束时不执行。

## 任务更新

任务以 chatKey 隔离，保存 ID、目标、类型、参数、排除项和状态。多个任务可同时存在，未能明确指向时追问。

例如先提出罗大佑歌曲任务，再纠正“我说的是乡愁四韵”，更新 title，保留 artist 和秒数。将 PPT 改为 Word，保留原主题，只修改 format。Manager 会将结构化参数、排除项传递给专业 Agent，并限制文档工具与指定格式一致。

否定旧对象只更新排除项并询问正确对象，不自动换一个执行。status 直接读取任务状态。普通 chat 只开放时间和历史/媒体查询工具，不开放记忆写入、绘图或其他执行工具。

未开始的草稿可以取消。运行或排队中的任务暂不支持可靠取消/替换，系统会明确说明没有修改原任务，避免并发执行第二份。管理模式允许状态查询进入第一层，不必等长任务执行完再回应。

状态是当前进程内的数据，最多保留 1000 个会话、每会话 20 个任务；结束/草稿任务 24 小时后过期，重启后不恢复。它不是持久工作流引擎。空间行动日志仍单独持久化。

## 翻唱执行边界

开启管理模式后，原来在 index.js 中提前触发的自然语言点歌、纠错和翻唱分支被绕过。Manager 只使用验证过的曲库条目或音频来源调用专用适配器。

- 指定歌曲必须歌名规范化后准确匹配；指定歌手时同时准确匹配歌手。
- 歌名、歌手、献唱对象分别保存在 `title`、`artist`、`recipient`。例如《30岁的女人》的数字属于歌名，不自动解释为时长。`delivery` 区分 `current_chat`、`other_chat`、`unclear`；歌手/接收人或交付位置不清楚时追问。
- 翻唱可以交付给已登记的好友：仅主人/管理员私聊，原始指令明确说“私发给某某”，且 QQ 号或登记昵称唯一准确匹配后才授权。仅献唱不等于跨聊天发送；生成前和发送前重新核验收件人权限。模型不能直接提供收件人授权对象。其他类型任务仍不支持直接交付到其他聊天。
- 私发投递只调用一次 QQ 接口，写入 `data/cover-deliveries.json`，分别记录 `sending/sent/failed/unknown`。没有确认回执不声称已发送，失败不自动重发；重启将中断的发送视为未知。等待下一条音频可以保留同一任务的投递授权，不能跨用户或更换收件人复用；过期需重新指定。使用方法见 [翻唱配置](COVER-SETUP.md)。
- 同歌手其他歌曲不能作为替代；存在多个同名版本时追问，不自动选择第一个。
- 曲库未启用、翻唱服务未配置、资源不存在时不执行。
- 只读搜索也修复了歌名零分、仅凭歌手加分就成为候选的问题。
- 当前附件与最近音频由 source 显式区分；最近音频限定当前会话、30 分钟内，不与歌曲来源互换。
- 管理模式的指定歌词起点、音频附件分段暂不自动执行；无法可靠核验时明确说明，而不是退回从头唱。
- 音频完成实际发送后才报告翻唱交付成功，异常不伪称成功。
- 显式 `/` 管理命令仍走旧命令路径；关闭开关恢复旧自然语言处理路径。

管理模式普通请求不再经过旧的自动补绘图、补文档等兜底。文档/原创歌曲排队后由实际后台结果将任务更新为完成或失败。控制台预览不执行这些后台交付，可能保留排队状态。

## 扩展与限制

领域事实校验通过 validators[kind] 注入，不能直接发送消息或执行生成任务。当前已落地曲库/音频来源核验和文档格式约束；并未实现所有领域事实核验。

附件内容仍属于不可信证据；身份、来源、否定约束在提示词中明确区分，但提示词不是完整注入防护。自然语言分类仍由模型完成，不能宣称任意措辞都识别正确。多意图混合请求中的翻唱目前使用专门路径，不会与其他产物自动联合规划；应分开提出这些请求。

## 验证

```bash
node --test --test-concurrency=1 tests/*.test.js
```

使用确定的模拟模型输出验证状态机、工具限制、失败路径和真实机器人接入；使用模拟 OneBot 验证新旧绘图流程，以及“曲库只有光阴的故事，要求乡愁四韵”不误触翻唱。

这不是实际模型的语义准确率评测。接入真实模型后，应继续积累否定、纠正、语音错字、指代、多任务和附件指令混淆样例，统计误执行和不必要追问。

## 通用操作约束（第三版）

第一层增加必需的 `operations` 和 `forbiddenOperations`。角色只能使用本轮操作所允许的工具，不能因为“这个 Agent 会做”就任意调用。操作目录在 `src/agents/capabilities.js`，当前覆盖聊天、记忆读写/公开、文档、看图/画图、表情、语音、哼唱/原创歌、检索、汽修和翻唱。空间发布/传话识别为不支持的执行操作，不偷偷完成混合任务中的其他部分。

- 文档：主题、格式、PPT页数、Word小节数、Excel行列数、读者、风格、数据来源。
- 图像：区分看图和画图，记录画面、风格、尺寸、参考图片；读取失败时不能依据图片执行。
- 语音：朗读原文与唱歌分开；目前超过120字要求分段，不截断。
- 资料：明确 query，查询工具不能越权生成文档。
- 汽修：至少有名称/描述或已识别图片；仍需区分类别判断与实际车型适配。
- 记忆：读取、私有写入和公开写入分开；公开写入还需要明确公开意图并经过原有主人权限检查。
- 附件：区分当前图片、当前文件和历史文件；缺失、读取失败、文件名不匹配、多文件未选择时追问。当前暂不自动批量处理多附件，也不自动解析未定位的历史附件。

确认过的参数在工具适配层重新绑定，防止模型改掉主题、格式、页数或朗读原文。禁止配图同时传递给 PPT 后台生成，不只禁止直接调用绘图工具。

Excel 必须明确使用已有数据还是允许示例。真实数据不存在时追问；已有数据模式下，后台提示禁止补造数字，示例模式要求标题标注示例。这里尚无独立逐单元格事实核对，因此不能保证模型绝不会产生数字错误。

每个产生副作用的操作都检查是否有相应工具成功记录。缺少调用时标记未完成并给出固定提示，不能只凭模型“做好了”结束任务。工具结果中的自然语言错误目前仍沿用文本识别，尚非所有工具都有结构化回执。

明确写入禁止清单的“不要画图，只做PPT”无需重复追问；否定范围未知或与操作冲突时才复核或追问。约束解除需要重新创建任务，避免修改时意外丢掉旧约束。

测试使用本地模拟模型与接口，覆盖执行边界和任务更新，不代表真实模型在所有口语、转写错字上都能正确抽取上述字段。需在后续真实模型联调中补充错误样本。
