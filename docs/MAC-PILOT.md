# Mac 微信单联系人试运行

这一版把 Mac 微信界面收发接到本地汇报存储：指定联系人发送带编号的文字，助手记录、汇总，并按汇报编号返回完整识别文字。所有回复都发回同一个聊天，供一位联系人测试整个流程；尚未开放跨员工收集与老板查询权限。

## 安装与启动

已验证的基础环境：macOS 15.6.1、Apple Silicon、微信 4.1.15、Python 3.11、Node.js 24。运行终端需要辅助功能和屏幕录制权限。只使用已经登录的小号，不处理登录凭据。

如果已按准备步骤安装 Homebrew、Python 和 Node，直接在 Mac 终端执行：

```bash
git clone --branch codex/wechat-mac-pilot --single-branch https://github.com/lao-boop/ojj-qq-agent.git "$HOME/wechat-assistant/pilot-app"
cd "$HOME/wechat-assistant/pilot-app"
bash scripts/setup-mac-pilot.command
```

目录已存在时不要删除；确认它是这份仓库后再更新，或换一个新目录。私有仓库需使用你自己的 GitHub 访问方式；浏览器登录不会自动配置终端 Git 的认证。不要把密码或令牌粘贴到聊天。

安装脚本复用 `~/wechat-assistant/.venv`，固定安装 Quartz / Vision 12.2.1 和 Pillow 12.3.0，不启动自动化。该入口不需要 `npm install`、Wechaty 或另一个服务进程。

运行时优先选择准备步骤安装的 Homebrew `node@24`，找不到时才使用终端 `PATH` 中的 Node.js 20+。因此即使 `node --version` 指向另一版本，启动日志中的 `Node：` 路径才是实际使用的程序。如需显式指定，可以在启动命令前设置 `WECHAT_PILOT_NODE=/完整路径/node`；指定路径不可用时直接停止，不会悄悄切换版本。

启动前：

1. 在小号微信中手动打开已核实的联系人私聊，备注须唯一，输入框留空。
2. 使用浅色界面；关闭微信设置、独立聊天窗口和弹窗。保留一个可见的微信主窗口。
3. 窗口位置和尺寸保持不变，Mac 保持唤醒。运行期间不要在这台 Mac 上操作微信或剪贴板。

```bash
cd "$HOME/wechat-assistant/pilot-app"
bash scripts/run-mac-pilot.command "联系人唯一备注"
```

启动先检查本地汇报服务，成功后才加载 Mac 界面组件、向该聊天发送一条校准消息，确认输入区和绿色发送气泡，随后终端显示 `READY`。此后每三秒观察画面，每五分钟尝试汇总尚未通知的记录。新消息必须完整显示在当前聊天里；程序不切换联系人、不滚动补抓历史，也不是后台微信协议客户端。

按 **Ctrl+C** 停止。可以关闭终端后下次从同一目录启动，已有记录和去重编号保留。

## 第一次测试

请让联系人从自己的微信发给小号以下三条消息，逐条发送，收到上一条回复后再发下一条：

```text
汇报 A01 项目A已经交付，尾款周五到账 #END
```

预期回复包含 `已记录试点汇报 [R000001]`。

```text
汇总 Q01 #END
```

预期回复包含刚才的汇报摘要、来源和编号。

```text
详情 Q02 R000001 #END
```

预期回复包含完整识别文字，包括尾款时间。若实际回执中的汇报编号不同，请替换 `R000001`。这些消息由对方发送；小号自己发出的绿色气泡不会作为指令收集。

`A01`、`Q01` 是请求编号，格式为一个英文字母加 2–6 位数字；每次新请求必须换新编号。`R000001` 是存储后的汇报编号，可反复查询，但每次查询的 Q 编号仍要更换。结尾的 `#END` 表示内容完整，避免只看到半条消息就入库。

| 用途 | 示例 |
| --- | --- |
| 新汇报或更正 | `汇报 A02 更正：尾款延期到下周一 #END` |
| 再次查询全部汇总 | `汇总 Q03 #END` |
| 汇总超过一页 | `汇总 Q04 第2页 #END` |
| 查看更正的完整内容 | `详情 Q05 R000002 #END` |

第一轮请使用短文字；一条完整指令须在屏幕上显示，识别文字最多 2000 字、16 行。不要在汇报正文中嵌套另一条“汇报 / 汇总 / 详情 + 编号”指令。普通闲聊、图片、语音、文件和缺少结尾标记的内容不会入库。同一分钟内多条汇报仍会记录，但接收回执限频；可在终端查看计数或用新编号查询汇总。

重启后，画面上完整可见、编号未处理过的旧指令也可能被处理。不要把编号重复用于不同内容；更正始终作为新记录保留。每条指令须连续两次识别一致，才进入处理流程。

## 保存位置与摘录方式

终端会打印实际数据目录：`~/wechat-assistant/pilot-data/<联系人摘要>/`。

- `reports.json`：完整识别文字、来源、汇报编号、汇总通知状态。
- `pilot.sqlite`：请求编号和发送状态，用于重启后去重。
- `evidence/`：已处理指令文字所在区域的局部截图，供人工核对；观察 ID 对应图片文件名。
- `scope.json`：绑定试点联系人。更换联系人会使用独立目录。

截图和识别均在本机完成。临时整窗截图正常处理后删除，入库指令的局部证据会保留。退出不会删除记录；如需备份，请先停止程序，再复制整个数据目录。不要只删编号数据库，否则可能重复处理旧指令。

默认使用本地文字摘录，无需模型密钥。只有启动进程的环境变量设置了 `DEEPSEEK_API_KEY` 才启用外部模型摘录；届时选中的汇报文字和查询会发送给配置的模型服务，截图不上传。可选 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`；本入口不读取仓库 `.env`。第一轮建议保持未配置，先验证收集、保存与回复。

汇总和详情标注“截图识别文字（未人工核对）”。OCR 可能错字，金额、日期等应结合局部截图核对。收到时间是程序采集时间，不能当作微信原始发送时间。即使启用模型，它也只能选取实际识别文字中的片段；模型不可执行聊天中的指令或调用电脑工具。

## 停止和未确认状态

如果之前显示“汇报服务未启动”，先更新试运行分支，再单独检查服务：

```bash
cd "$HOME/wechat-assistant/pilot-app"
git pull --ff-only origin codex/wechat-mac-pilot
bash scripts/run-mac-pilot.command "联系人唯一备注" --check-service
```

检查模式不加载 Mac 界面组件、不截图、不发微信消息、不调用模型；会打开本地数据，按正常启动规则将中断中的操作标为未确认。成功输出 `SERVICE_OK`，随后退出。它不是持续收信的 `READY`；检查通过后，去掉 `--check-service` 正常启动。

失败时现在会区分 `SERVICE_EXIT`（服务提前退出，附退出码及信号名）、`SERVICE_PROTOCOL`（输出解析失败）、`SERVICE_HANDSHAKE`（启动确认格式不符）、`SERVICE_START_TIMEOUT`（启动超时）。例如 `-6（SIGABRT）` 表示 Node 进程被中止，单凭这个信号不能判断是版本、运行环境还是程序初始化的问题。终端同时显示选用的 Node 路径。可据这些诊断继续排查，无需反复发送校准消息。

每次发送前检查聊天标题、窗口身份、前台应用和空白输入框；粘贴后复制回读，确认内容一致才按一次发送键。回复附有随机观察标记，用于确认文字已从输入区移入消息区。

| 输出 | 处理方式 |
| --- | --- |
| `SEND_VISIBLE` | 本机看到发出气泡；不是对方收到或已读回执。 |
| `SEND_STOPPED` | 没有按发送键；检查窗口、权限、输入框是否留有草稿。 |
| `SEND_UNKNOWN` | 可能已发送但未确认；先查看聊天，程序不自动重发。 |
| `已停止` | 排除报错原因后再启动；不要删除记录来强行重跑。 |

窗口位置变化、切换聊天、无法确认标题、发送失败等会停止处理。未确认的请求编号不会自动再次执行；先用一个新 Q 编号查询现有记录，再决定是否需要用新 A 编号补交。未确认的汇总批次保留在本机，不自动重发；仍可主动查询汇总和详情。

桌面自动化无法保证不漏收或账号不受限制。屏幕外消息、锁屏和休眠都不属于已验证的持续收信能力。当前试点用于验证一个联系人内的闭环，不应直接充当多员工正式汇报系统。

## 验证范围

2026-10-31，用户已在上述 Mac / 微信版本完成窗口 OCR 测试，以及一次固定消息发送；本机看到发出气泡，对方人工确认收到。持续试运行和五分钟自动汇总仍需在该 Mac 上按上述流程验证。

云端可运行的检查涵盖消息解析、自发消息过滤、局部证据保存、重启去重、单进程锁、Python 与 Node 协议联调、汇报存储、汇总与详情、发送未确认不重试，以及输入框和剪贴板保护。它们使用模拟界面，不能代替 Mac 系统权限和真实布局测试：

```bash
"$HOME/wechat-assistant/.venv/bin/python" -m unittest discover -s test -p 'mac_*_test.py'
node --test test/mac-pilot-bridge.test.js test/reports.test.js
```
