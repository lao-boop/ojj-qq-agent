# 精确核算、硬条件和新题评测

工作分支 `fix/architecture-routing-report`，main 未修改。生产改动增加只读核算工具，没有训练或微调模型权重。

## 执行路径

- `numbers.verify` 是 conversation 工作流中的核算操作，对应 `verify_numbers`。意图为金额、数量、比例核算或条件筛选时，必须拿到工具回执才能完成任务；普通编号和原文复述不触发。
- `src/numbers.js` 用 BigInt 有理数计算十进制加减乘除、括号、百分号，避免浮点误差；提供精确分数、显示数值及舍入标记。除零返回不能计算的说明，不编增长率。算式有长度、层数和数值大小限制，不执行任意代码。
- `decision` 逐条核对数值和布尔条件，将候选项区分为合格、不合格、信息未知；缺失属性不能通过。推荐字段若指向不合格或未知选项，工具报错，不允许用文字宣称完成。
- 只兼容确切的 `"true"` / `"false"` 布尔字面量格式，不使用会把 `"false"` 转成真的 JavaScript 真值转换，也不将“未知”猜成支持。
- 语义理解器读取最近八条真实对话以理解改口和指代，区分聊天答案的修改与执行任务的修改。实际工具授权、任务取消和文档排队仍受原工作流约束。

仍有边界：数据和条件由模型从自然语言提取，工具只验证传入内容，不能证明所有约束都被正确提取。最终文字也由模型组织；这不是完整的数学证明或事实核验。文档排版、QQ发送不在本轮测试范围。

## 可重复运行

```bash
node --test tests/*.test.js
node --use-env-proxy --use-system-ca scripts/evaluate_response_quality.mjs \
  --live --suite=scripts/response-quality-holdout.mjs --out=tmp/holdout-new-run
node scripts/response-quality-report.mjs tmp/holdout-new-run
```

需要环境中安全配置 `DEEPSEEK_API_KEY`。只在给定 `--live` 时请求真实模型，不要将密钥写入命令或报告。`--source-root` 可指向保留的代码快照；每轮记录源文件哈希并拒绝覆盖既有结果。

## 本轮留存

新题 `scripts/response-quality-holdout.mjs` 在生产修改前固定：20个独立场景，另4个关键场景重复一次；重复题不能算新独立样本。采用与上一轮相同六维0～2分、总分至少10且无0分/关键错误的标准，按完整多轮对话评分。服务异常单列，不当作通过，也不当作内容错误。

- `tmp/holdout-before`：修改前完整基线。
- `tmp/holdout-after`：首次接入核算后的完整运行，保留布尔参数类型失败。
- `tmp/holdout-final`：修复明确布尔字面量格式后的完整重跑。
- `tmp/numeric-regression`：原21题中的3道计算/预算题回归。
- `tmp/numeric-regression-final`：最终生产代码对应的同3题回归，3/3达标。
- `tmp/holdout-errata.json`：评审资料勘误。第一题退款实付为110.40元，人工期望曾误录为110.50元；发现后纠正，两轮用户输入未变，旧结果原样保留，全部版本统一按正确算式评审。不能把评审资料错误算在被测模型头上。

首次新题输出后修复了通用参数格式问题，最终复测属于已知题回归，不能宣称完全盲测或生产满意度。历史报告和中间失败都保留，不拼接单题重试的最好结果。

## 结果与后续重点

| 版本 | 全部尝试 | 达标 | 内容需改进 | 服务超时 |
| --- | ---: | ---: | ---: | ---: |
| 修改前 | 24 | 22 | 1 | 1 |
| 首次接入 | 24 | 18 | 4 | 2 |
| 布尔格式修复后 | 24 | 21 | 1 | 2 |

最终内容达标21/22（95.5%），但完整尝试达标21/24（87.5%）；修改前为22/24。两轮共同有完整输出的22项，均21项达标。原预算题从上一轮9/12变为11/12，正确算出49元且明确选A，但新题总体达标数未提升，不能将局部修复当作整体成功率提高。

两项超时发生于“修改预算”和“纠正箱数”的第二轮意图识别；同一箱数更正在预先安排的重复场景成功。一个内容问题仍是“仅本次参考、只给一个热饮”被扩写成以后承诺和两个建议，没有发生实际长期记忆写入。

核算增加模型往返：成功模型调用63→78，输入token 167219→248536；场景耗时中位数约23.8→26.1秒（并发和服务波动不同，非严格性能基准）。下一步宜单独诊断意图识别超时和压缩回复，而非继续增加提示词长度。
