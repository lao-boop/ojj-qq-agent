# 小鲸鱼接入企业微信

企业微信通道使用官方 `@wecom/aibot-node-sdk` **1.0.7**，通过智能机器人的 API 长连接接收消息、调用小鲸鱼的对话与工具能力，再将回复发回企业微信。

- [官方 Node.js SDK](https://github.com/WecomTeam/aibot-node-sdk)
- [企业微信智能机器人长连接文档](https://developer.work.weixin.qq.com/document/path/101463)
- [腾讯官方接入说明](https://cloud.tencent.com/document/product/1759/121473)

## 创建机器人并启动

1. 在企业微信管理后台的「智能机器人」中创建机器人，选择「API 模式」和「使用长连接」，保存并取得 **Bot ID**、**Secret**。根据后台设置开放使用范围；群聊时将机器人加入目标群。
2. 在项目根目录的 `.env` 中填写：

   ```dotenv
   CHAT_PLATFORM=wecom
   WECOM_BOT_ID=你的BotID
   WECOM_BOT_SECRET=你的Secret
   DEEPSEEK_API_KEY=你的模型密钥
   ```

   Secret 和模型密钥只填入本地 `.env` 或运行环境的密钥设置，不要发到聊天、日志或提交到 Git。已有模型密钥可以继续使用。
3. 安装依赖并启动：

   ```bash
   npm install
   npm start
   ```

   也可以用 `npm run start:wecom` 明确启动企业微信通道。
4. 打开本地控制台 `http://127.0.0.1:3010` 查看连接状态。等待机器人认证成功后，给机器人发私聊消息，或在群内 `@机器人` 测试回复。

程序主动连接 `wss://openws.work.weixin.qq.com`，无需公网 IP、域名或 HTTP 回调地址。运行机器需要能够访问企业微信长连接服务和配置的模型接口。

如果运行环境设置了 `HTTPS_PROXY` / `HTTP_PROXY`，企业微信长连接会沿用对应代理，并遵守 `NO_PROXY`。代理返回 `CONNECT 403` 表示在企业微信认证之前网络隧道已被拒绝，应先检查运行环境到 `openws.work.weixin.qq.com:443` 的访问策略；更换 Bot Secret 无法修复这个错误。

**同一个 Bot ID 同时只运行一个实例。** 新连接会让旧连接收到断开事件；不要在两台机器上同时启动同一个机器人。此模式使用智能机器人的 Bot ID / Secret，不使用旧式群机器人的 Webhook 地址，也不需要自建应用的 AgentID。

## 人设、记忆与功能范围

- 企业微信使用独立人设 `data/persona.wecom.md`，会话键以 `wecom:botid:...` 开头，区分机器人与会话。配置了 `QQBOT_DATA` 时，数据保存在指定目录中。
- 企业微信不载入 QQ 的全局记忆。QQ 和企业微信的人设、会话上下文分别维护。
- 支持私聊、群聊，以及通道实现支持的文字、图片、语音转写和文件处理。企业微信收到的语音消息已包含转写文本。
- 图片生成需要配置相应出图后端；语音合成需要 Python 和 `edge-tts`；文档读取、生成需要对应 Python 库，如 `python-docx`、`python-pptx`、`openpyxl`、`pypdf`。音频格式处理还可能需要 FFmpeg。缺少这些依赖不会自动补齐相应能力。
- 企业微信通道不开放 QQ 空间、Minecraft、QQ 传话、QQ 全局记忆、曲库点歌与翻唱功能。

控制台的「企业微信权限」默认允许机器人可见范围内的会话；可切换为白名单模式，分别填写成员 UserID 和群 ChatID。企业微信 ID 是字符串，不是 QQ 号。空白名单在白名单模式下不放行。

私聊可用 `/help` 查看帮助、`/reset` 清空自己的会话、`/cancel` 取消自己发起的后台任务。群聊共用本群上下文，清空群记忆请使用本地控制台。取消会停止后续处理；已提交云端的请求可能仍会计费。

回复文本通过企业微信流式消息发送：先显示处理中状态，再用最终文本替换。图片和文件通过企业微信素材接口传输，不依赖 SnowLuma 或 OneBot。
MP3/WAV 等合成音频作为文件发送；收到的视频暂不解析，可改发截图。文档和完整歌曲在后台生成，成功上传后才记录为已交付。
控制台的「在线测试」只预览人格和对话，不执行工具或向企业微信发送消息。

## 秘书汇报与原文追溯

在控制台「配置 → 秘书汇报与消息溯源」填写汇报接收人的企业微信 UserID，并启用。默认间隔为 60 分钟；有新增的其他成员消息才发送，不汇报接收人自己的消息。汇报发到接收人的私聊，不发到群里。

- 只保存启用后机器人实际收到、且通过访问范围检查的消息。无法读取员工之间没有发送给机器人的聊天，也不会补造启用前的记录。
- 原文单独保存在 `data/wecom-secretary/`，不依赖可能被压缩或清空的对话摘要。保存消息编号、发送者 UserID、会话 ID、平台 msgid、本机接收时间、可用的平台消息时间、身份快照和原文；报告显示北京时间。姓名仅来自企业通讯录或管理员名单，未知时只显示 UserID。
- 文字保留原文；语音注明平台转写；引用注明是引用，不据此猜原作者；文件正文提取结果与原消息分开标记。图片、视频只记录附件类型，本版本不为它们建立视觉内容检索。临时下载 URL、AES 密钥和机器人凭据不进入消息档案。
- 接收人可以自然地问「今天其他同事说了什么」「查一下蓝鲸计划的进展」。模型先检索原文，必要时补读同一会话上下文，再用短段落说明事情、最新变化和未确定的部分。默认不堆消息编号、秒级时间或重复原文；模型归纳可能有误，事实以来源原文为准。
- `/汇报` 归纳最近 24 小时的最新 10 条消息；`/查消息 关键词` 检索并归纳，超过展示范围时注明覆盖限制。`/来源` 展开上次查询或已确认发送的汇报依据，每页最多 3 条，`/来源 2` 翻页；`/原文 M编号` 查看完整原文，长消息按提示使用 `/原文 M编号 偏移量` 继续读取。也可自然地要求「看看刚才那件事的原话」。
- 跨用户查询工具和命令仅限配置接收人的私聊。其他成员和群聊不能借助指令、自称管理员或引用文本查询他人消息。对话预览页不执行这些工具。
- 定时报告调用配置的语言模型理解新增原文，并带入少量同会话背景。程序校验输出结构和来源编号是否存在；判断、建议明确标注，语义准确性仍需以原文核对。每轮最多处理 40 条，分批生成短报告；积压内容后续续报。摘要失败不推进进度，60 秒后重试，不用原文洪流替代摘要。发送 ACK 成功后保存进度；断线或重启后续传已生成但未确认的部分，不重复生成。若服务器已接收但 ACK 丢失，重试可能造成重复投递，不能承诺严格一次送达。
- 程序和 Mac 需要保持运行。睡眠、关机或断网期间不会按时发送，恢复运行后补报。本地控制台可以关闭汇报或更换接收人；关闭后暂停记录、汇报及跨用户查询，既有档案保留。

### 消息理解架构

本次参考用户提供的 `deliverables_TangShiyang_v2.zip` 中 `3905ChatBot`（MIT，ShiyaNgtAng-river）的设计思路：保存原始消息、提问时按需检索和补读、把摘要作为导航、由程序掌管身份权限与来源。没有复制其代码、聊天数据或评测数据，也未把它的评测成绩作为本项目成绩。

本项目仍采用现有关键词检索和模型工具调用，没有移植完整的检索引擎或多代理系统。企业微信每轮最多 8 轮工具交互、24 次调用、60,000 字符来源读取；达到预算后根据已读内容回答。同会话前后文工具限制时间窗口与条数，并明确「相邻不代表回复或同一话题」。来源保存在独立档案和查询记录中，摘要不替代原文；发言人、被提到的人和引用作者不能混淆，后续更正优先于旧安排。

验证覆盖权限隔离、同会话上下文、读取预算、来源持久化、失败重试、投递确认与接收人切换；真实模型使用合成消息验证了零散描述合并、时间改口和定时摘要。没有使用真实员工聊天做公开测试，也不代表所有语音转写歧义都能自动消除。

### 文档收件箱与原文件转发（2026-11-17 合并上游）

整合主分支 `769b139`（包含 `6bb0f32`）的文档收件箱、文件转发、大文件接收和配置兜底，并适配当前企业微信入口。保留本分支的文档规划与校验、秘书自然汇报、原文追溯、通讯录身份、工具权限及发送确认逻辑。

- 启用秘书后，当前机器人收到的、访问范围内的私聊文档进入独立收件箱。群文件和引用里的附件不自动作为个人提交；QQ、不同机器人、生成文件和来件分开识别。历史版本尚未登记的文件不自动扫描补录。
- 负责人可问「谁交了文档」「把同事的文档汇总成Word」。默认查看最近48小时，每批最多20份；后台生成总体概览和逐份摘要，保留提交人、文件名、接收时间。未读完或无法提取正文时明确注明。模型失败、取消或发送失败均不标记完成；成功发送后才标记本批，余下文件可继续汇总。
- 「把采购方案再发给我」重发登记的原文件；「把采购方案转给小陈」通过企业微信发送给明确的员工。接收人同名或文件不明确时需要消歧，可指定提交人；不依靠聊天自称建立姓名映射。仅负责人私聊可以跨成员查询、汇总或转发；不自动广播文件。
- 收件箱最多400条，优先回收已处理记录，满箱时不丢弃待处理记录。每份摘要使用最多6000字符的提取正文，保留截断提示。完整附件仍保存在本地，摘要不等于原文件。
- 接收文件的本地上限扩大至100MB，QQ网络下载在读取中限流检查；企业微信SDK下载后检查大小。企业微信发出的附件仍受50MB上传上限约束，图片本地处理上限仍为8MB。平台或网络自身还可能有额外限制。
- 上游的“互转”指原文件转发，本次没有新增格式转换。配置兜底不会自动放开空白名单，合法的零温度和空唤醒词设置保留；日常文档工具持续可用，只有无游戏上下文时才隐藏大量Minecraft工具定义。

回归验证覆盖原有聊天/记忆/秘书/身份/附件/Office与代理连接测试，以及新收件箱隔离、同名消歧、待处理进度、权限切换、25MB文件、真实汇总Word解析。真实企业微信投递仍需在用户运行环境验证。

### 安装更新

2026-11-17 的聊天风格更新将日常接话与秘书汇报规则分开：普通聊天使用简短口语，寒暄汇报限制为一两句，具体金额、期限和变更继续保留。推断采用自然的不确定语气，不叠加“我的理解是/我的判断是”标签。控制台预览使用同一聊天风格。

首次启动时，仅当 `data/persona.wecom.md` 与旧版默认人格完全一致（忽略首尾空白）才替换为新的聊天人格，并备份到 `data/persona.wecom.before-conversation-update.md`。自定义人格（含空内容）、QQ人格、会话与权限配置均不覆盖。示例和真实模型烟测用于观察语气，不保证模型每次措辞完全相同。

`scripts/update-wecom.mjs` 根据固定提交的清单下载代码、校验 SHA-256、检查 JavaScript 语法，并备份旧文件。它保留凭据、Python 路径、聊天记录及已有秘书设置。首次升级才初始化秘书汇报；旧的默认文档模型 `deepseek-flash` 改为跟随主聊天模型，移除旧的默认配图间隔，并关闭本地画图冷却。自定义文档模型保留。升级前停止机器人。运行方式：

```bash
node scripts/update-wecom.mjs <完整提交SHA> <汇报接收人UserID>
```

更新只设置功能，实际定时投递需在用户的企业微信环境验证。

## PPT / Excel 生成架构与质量检查

处理链路：聊天模型识别文档任务 → 保留当前要求和最近用户材料 → Office 模型规划完整 JSON → `office-plan.js` 校验并反馈修正 → Python 渲染可编辑 Office 文件 → 企业微信后台任务发送。

- PPT 一次生成完整故事线，页数按含封面、结束页的总页数计算（3～24）。商务配色默认启用；支持卡片、双栏对比、时间线、表格、原生可编辑图表、图文和要点七类版式。长内容反馈给模型精简，不静默截断；细节可放演讲者备注。图表与文字有独立区域。
- 图表必须提供来自用户材料的数据摘录，校验数字是否出现、系列长度是否匹配；不允许把错误数字替换成零。此校验不等于语义审计：仍需核对单位、分类映射及模型归纳。用户明确要求示例时才允许生成标注的示例图表。
- Excel 明确区分整理真实数据、空白模板和用户要求的示例。最多5个工作表，每表20列200条数据，超限反馈修正，不截断。整理模式保留每行的原文依据供校验，数字用数值类型，计算列和合计由程序展开公式。
- 支持本表四则运算及 SUM / AVERAGE / MIN / MAX / COUNT。引用范围、除零、循环依赖和不可计算公式会阻止交付，最多修正两次。没有通过校验会明确报错，不发送看似完成却计算为空的表格。不支持的复杂公式需另行扩展。
- Excel 显示单位和数值格式、冻结表头、筛选、交替行色、合计强调和可选原生图表；保存公式的同时写入计算缓存，便于企业微信预览。文件扩展名修正为 `.xlsx`。
- 文档模型默认跟随主聊天模型，可用 `office.model` 单独指定。`office.imagesPerDeck` 为生成配图的上限，默认2，0表示关闭；仅图片版式会请求配图。无固定本地等待间隔，平台真实429仍按重试策略处理。配图失败时保留可读的文字页。
- 字体按生成环境选择：Mac 使用 PingFang SC，Windows 使用 Microsoft YaHei，Linux 使用 Noto Sans CJK SC（需已安装）；可通过 `OFFICE_FONT` 指定。文件在其他设备上的字体替代由阅读软件决定。

验证包括：原始要求传递、页数、数据来源、公式错误修正、取消任务、实际 Office 文件解析，以及固定样例经 LibreOffice 导出后的人工预览检查。`test/fixtures/office-plans.json` 保存可重复的七版式与采购预算样例。真实模型烟测也生成了8页演示及500元采购表；单个样例成功不代表所有主题都会有同等内容质量。

## 员工身份与消息时间

更新后，每次对话的模型上下文和历史记录都附带平台 UserID、可用的姓名/部门/职务、身份来源、平台消息时间与机器人接收时间。群聊逐条保留实际发言人的身份，不按群名或聊天自称判断。`/我是谁` 可直接查看当前身份，不调用模型。

姓名有两个来源，在控制台「配置 → 企业通讯录与身份识别」设置：

1. **自动查询**：填写企业 ID（CorpID）与可读取成员信息的企业自建应用 Secret，启用自动查询后保存。收到某位员工的消息时，通过 `gettoken`、`user/get` 读取该成员，`department/list` 补充部门名。仅查询实际发言者或管理员主动检查的 UserID，不批量抓取全企业通讯录。
2. **管理员名单**：粘贴 `UserID | 姓名 | 部门 | 职务`，一人一行；姓名必填，后两项可留空。也支持从表格复制的制表符分隔列（不含表头）。可以独立使用，优先于自动查询。员工在聊天中说“我是某某”不会修改这份名单。

自动查询所需的 Secret 来自「企业微信管理后台 → 应用管理 → 企业自建应用」，与智能机器人的 Bot Secret 不同。企业 ID 一般位于「我的企业」。应用的可见范围需要覆盖相关员工，并按管理后台要求配置运行机器的企业可信 IP。没有成员读取权限、IP 不匹配或网络失败时，控制台“检查姓名与部门”显示错误码，机器人仍可按 UserID 对话。依据：[读取成员接口](https://developer.work.weixin.qq.com/document/path/90196)、[长连接协议](https://developer.work.weixin.qq.com/document/path/101463)。本环境无法完成真实企业通讯录认证，需在实际运行环境配置后验证。

也可用环境变量 `WECOM_CORP_ID`、`WECOM_DIRECTORY_SECRET` 注入凭据（仍需启用 `wecom.directoryEnabled`）。Secret 在控制台返回值中脱敏，不放入模型上下文、原文档案或联系人缓存。仅缓存识别需要的姓名、部门、职务及查询时间，不保存接口返回的手机、邮箱等字段；缓存有效期一小时，查询失败时旧姓名明确标记过期。凭据变化后隔离旧缓存和未完成请求。

秘书档案记录消息处理时的身份快照，改名不重写旧消息。老消息没有快照时，可显示当前名单匹配结果，并明确标注“非历史快照”。按姓名查询支持同名员工，结果保留各自 UserID、部门和原文编号；权限判断始终只使用 UserID。所有时间显示为北京时间。平台未返回有效 `create_time` 时只提供接收时间，不猜测发送时间；检索工具的 `timeBasis` 可指定接收时间或平台时间，后者不包含缺失平台时间的记录。
