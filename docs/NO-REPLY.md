# 已连接但机器人不回复

`OneBot 已连接` 表示 WebSocket 已建立，`登录账号/机器人就绪` 表示登录信息接口也成功；这并不证明 NapCat 正在推送新消息。日志中的 `回复 private:...` 是回复内容已生成，QQ 是否发送成功还要看后续错误。

## 先检查消息入口

1. 保持 `npm start` 终端运行，用自己的 QQ 私聊机器人发送 `/status`。允许访问的账号可以使用这个只读命令；它不调用模型、不等待聊天/媒体发送队列，也不受普通聊天限流影响。群聊不走这个诊断入口。
2. 查看 `data/logs/bot.log`：`消息事件` 表示应用已收到事件，随后若有 `忽略未授权私聊`，核对 `access.ownerQQ`（填你的个人 QQ，不是机器人的 QQ）、`adminQQ`、`privateAllow`。主人和管理员无需重复加入私聊白名单。其他账号和群聊仍需原有访问权限。
3. 如果只有启动日志，没有消息事件，在新终端运行：

```bash
cd ~/qq-agent-dev/ojj-qq-agent
node scripts/diagnose_onebot.mjs
```

脚本从本地配置读取连接信息，只调用 `get_login_info` 并监听 30 秒；运行期间给机器人发送一条“测试”。它不会调用模型、发送消息、修改配置，也不输出 Token、API Key 或消息正文。机器人主进程若仍在运行，会正常处理这些测试消息。

- 未取得登录信息：检查 Docker/NapCat 是否运行、QQ 是否在线、3001 端口映射、WebSocket Server 启用状态、地址和 Token 是否一致。
- 登录接口正常但没有事件：确认消息发给了脚本显示的机器人 QQ，检查 NapCat 网络配置中的事件推送，以及猫猫日志是否收到消息。API 能连通不等于消息推送正常。
- 访问名单拦截：修正对应账号的访问配置后重启机器人。不要为了排障直接开放全部陌生人权限。
- 事件和访问都通过：查看机器人日志中“消息事件”之后的错误；可能在附件读取、模型调用或 QQ 发送阶段。保留错误类别和时间，隐藏密钥。

## 超时行为

`llm.timeoutMs` 是一次模型调用包含重试的总时间预算；不会每次重试重新获得完整超时时间。Manager 的意图解析、结构修复及后续模型调用也使用其剩余时间预算；已经发起的生成/发送任务不会因为超时自动重做。

OneBot 断线时，未确认的请求立即结束等待并报告“结果未确认”；这不表示对方一定没收到，不自动补发。连接恢复后可重新使用 `/status` 检查。
