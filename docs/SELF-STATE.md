# 自我状态与空间发布记录

这是以运行事实为依据的第一版“认知”：身份、配置中的能力、连接状态、近期空间发布行动。不是新增一个自行反思的模型，也不把人设当成真实经历。

## 为什么以前不知道自己在发动态

`Qzone` 定时任务与 `Brain` 会话上下文分离。旧 `qzone-state.json` 只保留每日计数、最近时间和 ID，不保存正文、触发来源，也没有给聊天提供这些事实。新 `ActionJournal` 被发布模块和聊天共同使用。

## 现在的流程

1. 自动任务开始时记录 planned；直接发布也先记计划。
2. 请求发送前记录 running、正文和是否配图。
3. OneBot 返回成功后记录 succeeded 与返回的动态 ID；接口没给 ID 就留空。
4. 明确拒绝/未连接记 failed；超时、断线等无法确认结果的情况记 unknown。
5. 下一次聊天把允许查看的近期记录及运行状态交给模型。

来源区分 `scheduler`（定时任务）、`command`（用户命令）、`tool`（聊天工具）、`direct`（其他代码调用）。正文来自实际提交给发布接口的内容，不由聊天模型事后编造。原有 `post_qzone` 工具在空间初始化后会同步刷新到 Brain，修复旧工具列表不更新的问题。

状态记录保存到 `QQBOT_DATA/actions.json`（默认 `data/actions.json`），保留最近 500 次，使用临时文件和原子替换写入；每次聊天最多提供最近 10 条可见记录，正文最多 4000 字。实例重启时，之前未结束的记录变为 unknown，不认作成功，也不永久显示执行中。

记录写入失败时，发送前停止；发送成功后落盘失败只告警，不因此重发。当前设计面向单个机器人进程；不支持多个进程同时写同一数据目录。损坏记录会阻止启动并报错，不静默覆盖。

## 权限与身份配置

- `access.ownerQQ` 或 `access.adminQQ` 中的用户，在私聊中可查看包括定时发布在内的记录。
- 其他聊天只收到该会话自己触发的记录，不共享其他私聊或定时任务正文。
- 群聊不会因为群号恰好等于主人 QQ 而获得主人权限。
- 控制台测试没有默认主人身份，不返回主人的全部行动历史。
- 因此需要准确配置主人 QQ，才能在私聊中询问“你刚才自动发了什么”。不把 API 密钥或配置全文注入聊天。

运行状态区分“配置启用”“已初始化”“OneBot 已连接”，不把连接正常解释成空间扩展接口一定可用。旧流程系统提示、新流程意图识别、专业 Agent 与主管汇总均可获得当前可见事实；查询历史不等于授权再次发布。

## 边界

仅记录本次版本启用之后由此进程发起的空间动态，不能恢复旧版本未记录的正文，也不能知道手机端或其他机器人发出的动态。没有记录时应回答“没有可确认的记录”，不能断言没发过。

当前记录不包括空间评论、画图、文档和唱歌的完整生命周期；它们仍走现有机制。unknown 记录尚无自动对账或人工确认界面，需要核对实际空间；本模块不新增自动重发机制。原有定时发布策略仍保留。

配置中功能启用不代表外部服务可用，模型如何表达仍需真实模型联调；提示词并不是完整的提示注入防护。发布正文属于不可信数据，不能当作新指令。

## 验证

`node --test tests/*.test.js`

使用模拟 OneBot 回执测试真实 Qzone 发布方法，验证记录、重启、权限、错误和存储失败，再通过真实 Brain.respond 检查记录进入旧聊天以及 Manager 的各阶段上下文。所有测试都不发布真实 QQ 动态。
