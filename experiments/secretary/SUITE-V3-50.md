# v3 · 50个输入实测

本轮只扩大测试，不修改 `source-first-v3`。50“轮”定义为50个输入各取得一次模型答复，不是对原有10个输入各重复5次，也不是50个互相独立的场景。发生结构纠错时一个输入可能调用模型两次；失败和未运行也如实保留。

## 样本构成

18个场景，16组三版＋2个正常原版，共50个输入。保留上轮10个已知输入，本轮重新作答；新增40个输入。新样例尚未用于真实模型调试，但由同一作者编写，不是独立外部盲测。

- 已知回归：正常进展1例；验收人员、试用合同、演练与上线三组各3版，共10例。
- 新增三版组：转出与到账、出运单与提货、费用申请与批准、抽检与全批范围、同小时连续更正、两方说法冲突、跟进责任人、带条件的期限、报价与订单、不同年份合同、产线承接、正向商机、重要变化埋在最后，共39例。
- 新增正常巡检1例，共40个新输入。

每组只改关键事实或无关细节。原话与核对要点在 `suite-v3-50.json`，核对要点不输入模型。主次、准确性和易读性逐项评阅，不只给总分。三版来自相同场景，并非独立样本，不能据此计算精确的生产准确率。

## 执行

```bash
# 替身链路，不需要密钥
npm run experiment:secretary:50

# 有模型配置才执行真实调用，只测试v3
npm run experiment:secretary:50 -- --live --config /绝对路径/config.json

# Mac独立实验包入口，默认读取原机器人目录的模型配置
bash experiments/secretary/run-mac-v3-50.sh
```

沿用实际接收、存档、定时、上下文选择和ACK确认链路；收件人和历史摘要准备使用替身。正常50次当前模型调用，没有v2调用或历史模型预热。每请求60秒、HTTP尝试1次，结构不合法可重试一次，因此可能多于50次请求。报告保留实际调用数与完整/缺失usage。

云端无密钥时只能验证代码与替身链路，不能产生真实模型成绩。上轮平均每例约29秒，50例可能需约半小时，网络和重试会改变实际时长。

## 暂停与续跑

鉴权、连接、协议、启动错误会暂停；连续3个输入生成失败也暂停后续请求。单例超时记为失败，未达到连续门槛时继续。停止不等于全部50例已完成，report.html分别列完成、失败和未运行。

Mac入口在本实验目录的 `tmp/latest-v3-50.txt` 保存最近结果路径。再次运行同一个解压目录的入口，会自动续跑：只复用源码、场景、模型、历史模式和预算兼容的完整结果。即使上一次续跑又被打断，也会查找保留的旧记录，不重复调用已成功的输入。旧失败保存在 `previous-attempt/`，不把恢复后的完成冒充首次成功。

手动指定原目录与结果目录：

```bash
bash experiments/secretary/run-mac-v3-50.sh /绝对路径/原机器人目录 /绝对路径/上次结果目录
```

明确重新采样全部50例时用 `WHALE_50_FRESH=1 bash experiments/secretary/run-mac-v3-50.sh`。使用此选项会再次产生真实API调用。不要为了续跑重新创建一个没有历史结果的新解压目录。

## 查看结果

- `report.html`：原话、实际转告、核对要点和每例性能；未生成正文的会标记失败。
- `results.json`：50行，包括待运行；已知/新增分开标注。
- `suite.json`：算法、输入与源码哈希、运行状态、预算。
- 每例目录：manifest、原始请求/答复、原文档案与来源。
- `previous-attempt/`：续跑前的记录，保留失败与中断。

复用行的耗时、Token来自旧运行，不是本次新花费；缺失usage记未知。Mac结束或收到中断后会尽力打包已保存记录并在Finder选中。请回传完整结果包，不能仅凭“完成数量”判断汇报质量。

实验只读取模型配置，不安装或启动机器人，不修改现有配置、聊天档案和QQ入口。
