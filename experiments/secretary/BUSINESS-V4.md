# 多人、多轮、多项目与有效上下文容量

当前为 **v4候选**，没有新的真实模型质量成绩。先前50例实际结果见[复盘](../../docs/reports/v3-50-2026-11-21.md)。实验不安装、启动机器人，不连接企业微信，不修改运行目录的配置或档案；仅从指定配置读取模型设置。

## 场景与测量

`business-v4.json` 固定7组、3位员工、每组3轮：跨部门签约与收款、抽检/返工范围、通电/测试与未来复核、寄样册/演示/预算/订单、未明确指代、无项目编号的两门店退款抵扣、同客户两楼栋签收安装。最后两组是新增保留场景，尚未用真实回答调试提示；并非外部独立盲测集。

1. **21轮自然汇报**：正式 `capture → tick → briefingMaterial → writeScheduledBriefing → 测试发送ACK`，三轮都有模型调用，不把以前的摘要当成事实来源。模拟ACK丢失后重发，断言不重复生成、ACK前不推进、无新消息不重发。上游企业微信权限入口及真实网络送达不在这个专项中，另有既有回归。
2. **容量诊断**：每组固定4问，在200/2000/10000条历史中分别测，共每档28问。历史含多人、多项目、不同事项交错；相关事实分布在早/中/后位置。容量档位固定同一业务日4小时窗口，随条数改变消息密度，避免同时改变时间跨度使“今天/明天”的标准答案失效；这是合成压力，不是现实日均流量假设。同档7组并非28个独立样本，跨档重复题也不能相加成独立样本量。
3. **完整依据对照（oracle）**：直接提供每场景全部相关原话，问同样问题，共7次；只用于分辨选材与理解，不代表正式检索效果。
4. **可选全量输入（full）**：全部历史直接放入模型输入。默认不开启，开启后增加最多21个单元。超显式字符预算不截断，记录 `budget-not-run`；接口拒绝和未完成单列，不能当作正确率为零或已测容量。

默认共49个单元（21轮汇报+21次检索后问答+7次完整依据问答）。正常49次请求，汇报结构修正至多再加21次。单请求60秒、HTTP尝试1次，网络/认证等请求失败暂停剩余付费调用；成功结果保留可续跑。

选择题使用共享的 `BUSINESS_READING_RULES`，但它是**独立诊断接口**，不冒充用户日常聊天或正式摘要输出。输入不含标准答案或标注依据。选项按固定种子打乱且跨档保持一致；程序按事先标注答案评分，不让模型自评。

## 必须分别报告

| 指标 | 含义 |
| --- | --- |
| 归档条数 | 历史记录规模，不含当前焦点消息 |
| 选入条数、字符、prompt_tokens | 模型实际收到多少材料；Token只用接口实际返回用量 |
| 依据覆盖 | 预先标注的所有必要原文片段是否被选入；离线可测 |
| 问题正确率 | 答对选项数/计划题数，同时列已完成、缺答、请求失败、未运行；未跑完不宣布最终成绩 |
| 严格有据回答 | 答案正确且引用覆盖标注片段；这是更严格的诊断，漏引不直接等于业务理解错误 |
| 自然汇报 | 展示员工原话与实际正文，人工看重要先讲、更正和未定是否准确、一遍是否读懂 |

归档1万条而只选入10条，回答正确属于**系统检索后的有效历史能力**，不是模型直接理解1万条。可选full模式才测直接长输入。不得拿离线依据覆盖率充当模型理解正确率。

初次离线结果：三档各27/28题所需依据被选到，正式选材每组8～10条；漏的是QM-41验收仍周五的最新确认。旧邻近选择器在这个远历史压力集中为0/28，不能推广成旧版实际正确率0%。本轮保留这个漏选，不根据单个题目继续定制排序。合成干扰记录具有模板重复，尚需增加不同长度、自然语言改写、关键事实位置和真实脱敏业务记录才能画出可靠容量曲线。

## 运行与续跑

```bash
# 本地无密钥：只验证选材、归档、定时、发送确认、结果记录
npm run experiment:secretary:business -- --out tmp/business-wiring

# 真实模型：会产生API调用，使用新的输出目录
node --env-file=/现有运行目录/.env scripts/evaluate-business-v4.mjs \
  --live --config /现有运行目录/config.json --out tmp/business-live

# 失败后新建输出目录，保留旧失败，复用相同代码/模型/预算下的已完成单元
node --env-file=/现有运行目录/.env scripts/evaluate-business-v4.mjs \
  --live --config /现有运行目录/config.json --out tmp/business-resumed \
  --resume-from tmp/business-live
```

Mac：`bash experiments/secretary/run-mac-business-v4.sh`。复用已验证的官方Node24缓存，读取现有运行目录配置。结束会打开HTML并在Finder选中结果包；同一解压目录再次运行自动续跑。保持联网和开盖；用 `caffeinate -i bash ...` 避免空闲休眠。配置不在默认目录时弹出选目录窗口。

可选全量：`WHALE_FULL_CONTEXT=1 WHALE_MAX_INPUT_CHARS=300000 bash experiments/secretary/run-mac-business-v4.sh`。字符预算不是Token预算；提高前需了解模型输入限制及费用。切换参数不能复用旧目录，设 `WHALE_BUSINESS_FRESH=1` 新开一次。

输出：`suite.json` 保存输入、调用、答复、用量、问题标准答案、评分和源码哈希；`metrics.json` 汇总；`report.html` 浏览；压缩档案可复现来源。续跑保留 `previous-attempt/`，包括中途被中断的嵌套历史。不会导出密钥或模型内部推理正文。

## 实现边界

新增选材仍是有限候选检索，不是长期事实状态库。项目编号匹配只用于找候选；不同年份、事项仍需模型分清。同一会话可按中文内容匹配，无编号的跨私聊关联暂不自动猜测。历史最多12条、每条最多1200字符，30天相关窗口；过长或未选中的原文不能假定模型看过。任何引用校验都不证明正文语义正确。
