## 改动与依据

- 旧实测中 staffing-key / staffing-irrelevant 丢失“下周一客户验收”。v2 每项显式选择必要历史背景，成文须在对应段落保留该短语，来源一并保存。只验证已选背景，不能声称已解决模型漏选。
- 事实计划移除重复改述 `text` 和排序理由 `reason`，成文仍拿到完整已选原文。保留状态、引用和更正关系；期望减少冗余，不宣称实际 Token / 延迟下降。
- 明确多人物时用姓名，计划不能写成“问过”，日常颜色等不影响理解时可省略。这部分是提示约束，需要真实答复复核。
- 定时请求仍60秒，HTTP尝试限1次；网络故障由秘书已有持久状态和退避处理。默认聊天仍3次。结构失败最多重试本阶段一次，不能说整份报告有硬性总截止时间。
- 新增安全的逐次HTTP耗时/状态、输出截断记录；新版实验双方采用相同60秒/1次策略。失败也保留，不能只统计成功样本。

## Mac真实模型对照

```bash
bash experiments/secretary/run-mac-v2.sh
```

默认读取 `~/Downloads/ojj-qq-agent-codex-wecom-integration` 配置，使用已下载的独立Node，不修改运行机器人。默认13输入×2版=26个运行单元（含历史阶段模型调用）；交替先后顺序，每版每输入只生成一次，不是重复采样或消融。
遇鉴权/连接/协议失败停止后续请求；60秒超时保留为预算实验结果并继续。可用第二个参数传旧结果根目录续跑，只复用哈希、模型、输入、选择与请求策略一致的完成结果，不覆盖旧结果。

结束自动生成 `comparison.html`、`comparison.md`、`metrics.json`、全部调用与档案；打开Finder选中结果压缩包。真实结果要看：背景是否选对、无关版是否稳定、计划/已完成是否保真、正常情况是否简短。程序不会自动给总分。

当前候选未代替用户Mac安装版。未得到v2真实答复前，不把结构测试、回放拦截和少写JSON字段算作质量/性能改善。
