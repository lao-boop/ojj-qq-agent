测试结果与调用证据

建议采用的三种测试

01 / 自动回归

先检验架构约束

模拟模型和 QQ 接口，检查权限、参数绑定、取消、跨会话隔离、超时和发送回执。每次代码更新都运行。

回答：程序是否守住约束？
02 / 真实模型 + 模拟工具

再检验真实指令路由

同一句话交给本机 DeepSeek，记录意图、Agent、工具名和参数。工具不产生真实副作用。先跑少量，再完整跑，关键场景重复3次。

回答：模型是否选对功能？
03 / QQ 端到端

最后核对真实产物

从 QQ 发消息、截图和文件，核对转写、数据、文件页数和送达结果。点击“人工通过/失败”保存自己的验收记录。

回答：交付的东西是否正确？
  • 真实模型通过率以“整个场景的所有轮次都符合预先定义的条件”为准；漏调、多调、参数错误或缺失依赖都算失败，不是通用识别准确率。
  • 真实模型测试使用预先解析的图片描述和文件文本，不测 OCR、视觉模型或 ASR 本身；它们必须在 QQ 人工验收中检查。
  • 当前 Manager 尚未接入通用传话与空间发布。对应测试要求明确停止并反馈，不能把“拒绝执行符合预期”解释为功能已实现。
  • 所有工具在实测脚本中均被替换为模拟工具，配置是否齐全、费用、实际生成质量与 QQ 送达不在该层通过率内。没有外部副作用不代表真实部署已验收。
  • 推荐准入条件：自动检查无失败；明确指令路由与参数全部符合预期；否定、越权、缺数据场景零误执行；随后逐项验收真实产物。

在你的 Mac 上生成真实模型报告

读取本机 config.json 的 llm 配置。仅模型文本调用计费，不发送 QQ、不调用绘图/语音/音乐服务、不写真实记忆。建议先测一个场景。

cd ~/qq-agent-dev/ojj-qq-agent
node scripts/evaluate_architecture.mjs --live --case=ppt
open reports/architecture-live.html

全量测试及稳定性复测：

node scripts/evaluate_architecture.mjs --live
node scripts/evaluate_architecture.mjs --live --case=research-document --repeat=3 --out=reports/repeat-live.html

不调用模型，仅更新自动测试报告：

node scripts/evaluate_architecture.mjs
open reports/architecture-report.html

每个实测场景结束都会保存 HTML 与同名 JSON。可以在这里导入 JSON 查看；人工记录存在当前浏览器，换电脑时先导出。新报告会替换同名文件，需保留历史时用 --out 指定新名字。
